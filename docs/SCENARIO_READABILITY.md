# SEA OF INFORMATION — 人間的な読みやすさ基準

最終更新: 2026-09-14

この文書は、普通の日本人プレイヤーが初見で遊んだときに「雰囲気はあるが意味が分からない」状態にならないための補助基準です。

`docs/SCENARIO_DIRECTION.md` のテーマ・構造ルールと併用します。

## 1. 基本方針

> 世界は複雑なままでよい。文章と会話は人間に寄せる。

SF用語や英語UIは本作の魅力なので消しすぎない。
ただし、プレイヤーが意味を掴む前に未知語を連続させない。

## 2. 「知りたい謎」と「単に分からないこと」を分ける

Sea序盤でプレイヤーに主に抱かせたい疑問:

- 私は誰なのか？
- ここはどこなのか？

DIVER、ARCHIVE、SIGNALなどの用語理解を同時に宿題にしない。

一場面でプレイヤーが抱える大きな未解決疑問は1〜2個を目安にする。

## 3. 未知語の借金を作らない

特に注意する組み合わせ:

- 未知の固有名詞
- 英語
- 技術用語

この3つが重なるほど、中二病的・雰囲気先行に見えやすい。

例:

避けたい:
`DIVE SIGNALを同期する`

採用方向:
`届いている信号に耳を澄ます`

## 4. Reiをプレイヤーの翻訳役にする

ReiはSFシステムへ即座に順応しすぎない。
すべての用語に聞き返す必要はないが、ときどきプレイヤーの「何それ？」を代弁する。

例:

SYSTEM:
`DIVER ACCESS / REI`

Rei:
「DIVER……ここに入る人の呼び方か。」

SYSTEM:
`CLOCK MASTER / DAWN CYCLE / SYNC: 08:42`

Noa:
「この時計、街全部の時間を決めてる。」

Rei:
「時計じゃない。スイッチだ。」

## 5. SYSTEMは専門的でもよい。人物まで専門語にしない

基本:

> SYSTEM = 事実・機械語
> 人物 = 感情・判断・普通の言葉への翻訳

難しいSYSTEM表示の直後に、人間側が短い言葉で意味を掴める構造は積極的に使う。

## 6. 英語UI

英語を減らすこと自体を目的にしない。

基準:

> 英語が読めなくても、その直後の出来事で意味が分かる。

比較的そのままでよい:
- SYSTEM
- DELETE
- RESET
- CREATE
- IDENTITY SCAN

文脈補強が必要:
- DIVER
- ARCHIVE
- RESTORE

ARCHIVEは場所・データ・メニューなど複数用途で乱用しない。

## 7. 操作文は「設定上正しい」より「何をすればいいか」

Gadget Areaのようなパズルでは、設備用語を知らなくても遊べる文にする。

避けたい:
- 主電源を迂回接続
- 歯車の位相を合わせる
- クレーンを退避させる

採用方向:
- 電源をつなぎ直す
- 歯車の印を合わせる
- クレーンをどかす

英語ヘッダーは演出として残してよい。

## 8. 会話の基準

City of Dawn、Noa、BIT、99.7%周辺の温度感を基準にする。

良い例:
- 「うわ。喋った。」
- 「傷だらけだけど。」
- 「じゃあ0.3%は私ってことで。」
- 「朝を……保存？」
- 「時計じゃない。スイッチだ。」

難しい世界観でも、会話まで難しくしない。

## 9. レビュー時チェック

- 初見で何をすればいいか分かるか
- 目の前で何が起きたか分かるか
- いま気にすべき謎は1〜2個に絞れているか
- 未知語を3つ以上連続で覚えさせていないか
- SYSTEMの専門語を人物が自然に噛み砕けているか
- 操作文が設備マニュアル化していないか
- 「意味は分からないけど格好いい」で終わっていないか
- City / Noa / BIT程度の人間的な温度感があるか

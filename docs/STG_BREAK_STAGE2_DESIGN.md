# Break — Stage 2 詳細設計

最終更新: 2026-09-17

状態: 未実装の設計仕様。採用範囲は3WAY弾とシールド型CORRUPTED NODE。記載の数値は試作初期値。背景制作を先に進め、今回Break本体・台詞データ・セーブ形式は変更しない。

関連: [STG全体設計](STG_OVERALL_DESIGN.md) / [現行後半シーン](../data/lateScenes.ts) / [音楽演出タイムライン](../data/pvTimelines.ts)

## 体験と物語上の目的

Stage 1で覚えた移動・連射・回収を使い、広がる射線と攻撃可能な時間を読む。新ボタンや装備は追加しない。管理系統の書き込み停止を背景に、Reiが経路を通し、BITが一時変更した保守経路を維持する。

CORRUPTED NODEは閉鎖に伴って経路を占有する異常データであり、保存記録や住人ではない。シールドは管理系統の保護周期を利用しているという演出案。管理命令そのものをすべて「悪」とせず、Dr. Reiの動機の開示は後半に残す。BITの判断をプレイヤーの成績で覆さない。

## 既存シーンへの組み込み

現行Breakは約302秒の演出タイムラインを持つ。`break-entry`の64秒・112秒の調査、172秒の`break-lock`遷移、186秒のBIT応答、282秒の脱出ゲートが存在する。既存台詞・必須フラグを削除せず、STGを次の位置に挿入する。

1. 0〜172秒: 現行の停止世界の調査・Listening・会話を維持。曲冒頭が激しくても学習前の高密度攻撃を出さない。
2. `break-lock`で既存`breakLock`と`breakOverride`を読み、`break.bitOverride`成立後に「経路を維持する」を表示。戦闘前に操作・評価条件を短く提示する。
3. プレイヤーが開始すると、Break楽曲位置186秒を戦闘チェックポイントとして明示的に再キューし、t=0から96秒のSTGを開始。会話を読む間に曲が進んだ場合も、残り時間を縮めたり序盤を飛ばしたりしない。これは現行にない再キュー仕様で、音切れ回避の短いフェードを実装時に検証する。
4. 楽曲282秒（t=96）で結果確定。残弾と未退場オブジェクトを消去し、結果画面から既存の`blavery-entry`へ進む。新規戦闘中だけ既存脱出ホットスポットを隠し、結果確定後は必ず進行可能にする。

時計は `t = audio.position - 186` に統一。メニュー・会話・タブ非表示で音声とシミュレーションを同時停止し、復帰時にキー入力をクリア、1秒の予告後に再開する。外部シークや大きな時間飛びは途中出現をまとめて処理せず、チェックポイントへの再開案内に切り替える。

旧セーブが`break-lock`途中の場合も必須会話後に同じ開始点へ案内する。すでにblavery以降へ進んだセーブをBreakへ戻さない。途中保存では戦闘の弾を保存せず、再開時は186秒から新しい1試行として開始し、過去のベストは保持する。再挑戦は結果画面から同じ開始点へ戻し、必須会話の再読は強制しない。

## 96秒の学習カーブ

時間帯はtの半開区間。出現は固定IDの手書きウェーブとし、区切りで周期を変更する床関数方式を使わない。以下の「上限」は画面内生存NODE数。出現予定を容量不足で遅らせる場合も予告を省略しない。

| t / 楽曲秒 | 内容 | 同時NODE上限・安全条件 |
| --- | --- | --- |
| 0〜8 / 186〜194 | 移動・連射の復習。通常NODE1体、発砲なし | 1体。開始時からSPACE使用可 |
| 8〜26 / 194〜212 | 3WAY射手2体を1体ずつ、十分な間隔で提示 | 1体ずつ。NOISEなし。予告から横／上下へ離れる |
| 26〜30 / 212〜216 | 休息、Echo 1 | 新規敵なし。残弾消去後に回収物を出す |
| 30〜50 / 216〜236 | シールド2体を1体ずつ提示 | 1体ずつ各10秒。射撃・NOISEなし。2開放周期を経験できる滞在時間 |
| 50〜54 / 236〜240 | 休息、Echo 2 | 新規敵なし。短い復習表示 |
| 54〜72 / 240〜258 | 通常NODE2体、3WAY射手1体、シールド1体を順次出す | 上限2体。シールドと3WAYの組合せは各単体練習後。NOISEは最大1個 |
| 72〜78 / 258〜264 | 休息、Echo 3 | 残弾を消し、通路を見せる |
| 78〜92 / 264〜278 | 3WAY射手1体＋シールド1体の最終組合せ | 上限2体。新要素なし。NOISE最大1個、2秒以内の再出現なし |
| 92〜96 / 278〜282 | 新規出現なし、退出と結果への余韻 | 残弾消去。未排除NODEは92秒までに退出判定を完了 |

固定総数は11体（通常3、3WAY4、シールド4）、Echo 3個。実装時に各IDの出現時刻・退場期限・配置をデータ化し、この総数と照合する。各単体練習は10秒以内に退場、複合区間は最終出現から退場まで最低10秒を確保し、最終組は78秒に予告開始する。区間終了で敵を無言消去して見逃しを隠さない。早く排除しても敵を追加せず、短い余裕を報酬にする。

Stage 1との差は短い復習から新しい射線と開放待ちへ進む判断負荷。Stage 1より常に敵数が多い必要はない。初回3WAYで事故が続く場合は予告を延長し、後半だけが簡単すぎる場合は複合ウェーブの間隔から調整する。

## 敵・被弾の初期パラメータ

速度は16:9の論理プレイ領域を正規化した値。発射角はピクセル比率を補正した空間で計算し、画面比率で3WAYの広がりを変えない。自機速度0.5/秒、連射105msはStage 1を基準として維持する。

| 対象 | 仕様 |
| --- | --- |
| 通常NODE | HP4、直進。復習時は発砲なし、複合ではStage 1相当の単発弾。見逃しはSYNC -9 |
| 3WAY射手 | HP4。予告開始時の自機方向を中心に±22度の3発。速度0.30/秒、発射間隔2.4秒、弾寿命3秒。発射後は直進し追尾しない |
| シールドNODE | 本体HP5。閉鎖2秒→開放予告0.8秒→開放2秒の周期。閉鎖中は無効、開放中のみ本体へ命中。閉鎖中に弾を反射せず、自身は発砲しない |
| NOISE | Stage 1相当の避ける障害物。速度0.20/秒から開始。初期導入は複合区間だけ |

3WAYは発射前0.9秒、3本の短いガイドと砲口の収束で方向を示す。初回は1.2秒に延長。発射原点が自機に近すぎる場合（論理距離0.28未満）は発砲せず、画面外や自機の背後から撃たない。左右の弾の隙間を抜ける以外に、扇全体の外へ逃げる経路を残す。同時3WAY射手は1体、画面内敵弾上限9発。上限で斉射を保留する場合は3発一組で保留し、後からまとめ撃ちしない。

シールドは外周の二重六角形で表示。閉鎖中の命中は小さな波紋＋控えめな「BLOCKED」、開放時は外周が左右へ離れ、白い芯と「OPEN」を見せる。色と効果音だけに依存しない。初回2体はx≈0.75に一時滞在し、最低2回の開放を保証してから退場する。開放中5発を当てる猶予を確保し、シールドの耐久削りや新しい溜め攻撃は要求しない。

SYNC初期値100、敵弾-11、NOISE-20、NODE見逃し-9、排除+6、Echo+9（上限100）はStage 1基準。被弾無敵0.8秒、被弾地点の近傍弾を除去する案。NODE本体への接触ダメージは追加せず、射線と見逃しに判断を集中させる。SYNCゼロで45に再同期し、周辺弾除去と2秒の安全時間を付ける。再同期でウェーブやEchoを増殖させない。

## 編隊・画面制御の候補と採否

| 候補 | 効果・予告 | 判断 |
| --- | --- | --- |
| 上下2体の時間差進入 | 通常NODEが1.2秒ずれて進入。高さを固定して優先順位を覚える | 複合区間の通常2体で採用。連動移動・斉射はしない |
| 本格的な連動編隊 | 3体以上が隊形を保ち一斉射撃 | Signalへ保留。Stage 2の新規学習を2種類に収める |
| 一時的な閉鎖レーン | 上か下の20%を1.5秒予告後、3秒閉鎖。自機の押し出しなし、残り80%に退避可能 | 初版では不採用。Stage 2が易しすぎる場合の再検討候補。採用時は3WAYと重ねずPERFECT条件も再評価 |
| 走査バー | 停止した世界を示す背景外周のゆっくりした走査 | 非接触の演出のみ採用候補。危険予告と同形・同色にしない |
| 入力反転・画面暗転・強制スクロール圧縮 | 操作や視認性を突然奪う | 不採用。読み取り能力より初見事故を増やすため |

## チュートリアルと表示文案

開始前: 「移動 WASD / 矢印・SPACE長押しで連射。今回は広がる弾と、開閉するシールドが出現する。」

- 3WAY初登場: 「3WAY — 予告の外へ移動」。ガイドを出してから撃つ。2体目は文を縮め、同じ予告だけで判断できるかを見る。
- シールド初登場: 「SHIELD — 開いた芯を狙う」。無効命中が続いたら「外周が開くまで待つ」を一度だけ再表示。時間経過でチュートリアルを延長・敵追加しない。
- 複合: 「弾を避けて、開いたNODEから排除」。以降は小さいラベルにする。
- BITの長い説明やEcho全文は戦闘中に表示しない。Echo回収は短い通知だけにして、休息区間・結果で読めるようにする。

これらはUI案で、現行台詞ではない。Reiの新台詞を追加する場合は既存の人物像・台詞整合チェックを通す。案内は一度に1要点、操作領域を塞ぐ大型パネルを常設しない。

## クリア・報酬・PERFECT

通常クリアは96秒区間の完走。撃破不足・被弾・再同期でもblaveryへ進める。主要ストーリーやBITの同行を高成績報酬にしない。

Echoは「停止直前の景色」「残された生成差分」「BITが確保した経路」の補足記録3件を新規制作する案。人類の生存やReiの正体など、必須の真相は含めない。26秒・50秒・72秒の安全区間で1個ずつ出し、中央付近へ到達できる速度と滞在時間にする。NOISE／攻撃を先に消し、回収時間は各区間の終端まで。全文は結果で再読できる。

| 評価 | 判定・報酬 |
| --- | --- |
| PERFECT SYNC | 完走、被弾0、NODE見逃し0、再同期0、Echo 3/3、11体すべて排除。結果の専用表示と3件を束ねた完全Echo記録 |
| STABLE | PERFECT以外で完走、再同期0、Echo 2個以上。取得済みEchoを保存 |
| DEGRADED | その他の完走。取得済みEchoを保存し、同じ次章へのボタンを表示 |

初回開始前と結果画面で条件を明示する。命中率・所要時間・背景ギミックの任意操作はPERFECT条件に加えない。11体にはチュートリアル対象も含む。敵の退出判定は1体1回、同じフレームで排除と退出した場合は命中処理を先に行い二重計上しない。

計測値は `hits / missedNodes / resyncs / purgedIds / collectedEchoIds / completed` を分ける案。Stage 1のdamageは見逃しも含むため、結果の説明にそのまま流用しない。レベル・EXP・装備強化は追加しない。リプレイで成績を改善でき、過去の収集・ベスト成績を失わない。保存は章進行と矛盾しない共通セーブ設計で行い、既存Load Roadの個別localStorage結果を無検討に複製しない。

## Break背景への発注条件

正式パスは `/art/production/break/break-background.webp`。凍結した生成世界と右奥に抜ける保守経路を描く。中央は暗く広い通路、外周に途切れた層と静止した構造物。x=0.07〜0.95 / y=0.13〜0.87の動作範囲には強い白光・細かい橙の粒子を置かない。停止帯・シールド・警告線・弾・文字は画像に含めない。

探索時の既存ホットスポット（停止景色18/36、BIT67/48、制御信号40/68等、単位%）にも対応できる構図とする。BIT本人を背景へ描き込まず、キャラレイヤーを配置できる余白を残す。1枚の背景で探索とSTGを兼用できるかを先に検証し、難しい場合だけ暗い差分を候補として制作する。共通要件は[全体設計の背景節](STG_OVERALL_DESIGN.md#stg対応背景の制作要件)を参照。

## 実装着手前・実装後の検証

- 背景制作後に、186秒への再キューが会話既読状態・音声管理・既存282秒ゲートと両立することを先に試作する。通常ロード／途中ロード／再挑戦を別々に確認する。
- 固定11体とEcho 3個が一度ずつ出現すること、シールド閉鎖中の無効・開放中の命中、退場の一度だけの減点、すべてのランク境界を自動テストする。
- 低フレームレート、タブ切替、メニュー、リサイズ、音声一時停止で不意の斉射・進行飛び・二重報酬がないことを確認する。
- 初見試遊で3WAY単体→シールド単体→複合の順に理解できること、全排除・無被弾・Echo全回収を同時達成可能であることを確認する。数値だけで公平性を確定しない。
- 16:9・4:3・狭幅、reduced-motion、SEを下げた状態でも予告が読めることを確認。タッチ操作は現在のキーボード基準とは別の未解決要件として扱い、対応済みと表記しない。
- 未解決の実装前判断は音声再キューの体験、セーブ統合方式、固定ウェーブの正確な配置、Echo最終文面。STGの役割・採用する2要素・通常クリア保証・背景の余白は本書の設計基準とする。

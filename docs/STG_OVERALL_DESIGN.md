## 目的と既存仕様

STGは楽曲と物語を体験する短い操作パートとする。15曲すべてを戦闘化せず、探索・対話・Listening Phaseとの緩急を守る。撃つ対象は経路を占有する異常データ `CORRUPTED NODE`。人間の記憶や生成された住人を破壊する行為にはしない。呼称は排除 / PURGEで統一する。

確認基準: dev `380aabdf6c2bd986c5e8f9d06f15f053a634d5a8`。

- [LoadRoadShootingStage.tsx](../components/stg/LoadRoadShootingStage.tsx): 移動、SPACE長押し、NOISE、MEMORY、NODEと自機狙いの直進弾が実装済み。発射後の追尾はない。
- 現行Stage 1は射撃解放が開始後25秒、通常NODEの敵弾が46秒以降。72秒超から追加NODE、110秒超で3体組の出現機会がある。これは出現組数であり、画面内総数の上限ではない。
- 結果判定は楽曲位置125秒。PERFECT SYNCは `damage === 0 && resyncs === 0 && memories === 3`。NODE見逃しもdamageに含まれる。SYNCゼロでも45へ再同期し物語は継続する。
- 現行は出現時間が開始相対、完了が楽曲絶対位置という違いがある。後続実装へそのまま複製せず、開始・中断・復帰の時刻を明示する。
- [lateScenes.ts](../data/lateScenes.ts)の後半ストーリーは実装済みだが、後半STGは未実装。設計上の追加機能と混同しない。

## 配置と学習の段階

| 区間 | 役割・新しく覚えること | 難易度の作り方 | 世界観上の意味 |
| --- | --- | --- | --- |
| Load Road / Stage 1 | 移動→回収→NOISE回避→連射→単発弾 | 単体練習を長めに取り、終盤だけ複数要素。最初の成功体験 | 朝の街の記憶を受け取り、DIVE SIGNALを次の記憶世界へ通す |
| Break / Stage 2 | 3WAY弾の予告と隙間、シールドの開放周期 | 数より判断を増やす。個別練習後に組み合わせる | 書き込み停止で閉じる経路から、BITが確保した保守経路へ抜ける |
| Signal / Stage 3 | 有限時間の追尾弾、連動する編隊 | 追尾を誘導して離れる→編隊の射線を読む→既習3WAYと交互に出す | 外部のLIVE信号を遮る異常を取り除く。地球外の送信者や船団は敵ではない |
| Thundercloud / Stage 4・ボス | 既習攻撃のフェーズ切替、攻撃を止めて接続を維持する判断 | 最も複雑だが、新操作は増やさない。フェーズ間に静かな対話区間 | 対象は閉鎖・巻き戻し処理の障壁。Dr. Rei本人の撃破や殺害を勝利にしない |
| Space Home / 非戦闘フライト | 自由移動と任意の光の回収 | 敵弾・ダメージ・失敗・PERFECT評価なし | CREATE後の未完成な未来を、自分の操作で進む余韻 |

Load Roadの2回目以降は移動・休息の役割を維持する。同じStage 1講習を毎回強制しない方針とし、初回シーンと再訪を区別する処理は将来実装で確認する（現行はartクラスに依存）。blaveryはBreak後の脱出とBITの選択を聞く区間として残し、連続STGにしない。

## 難易度カーブの共通規則

1. 新要素は一度に1種類。安全な予告→単体2回以上→既習要素との複合→短い休息の順とする。
2. Stage 1を相対負荷1.0とした体験目標はBreak 1.25〜1.4、Signal 1.5〜1.7、Thundercloud 1.8〜2.0。敵速度の倍率や測定済みの指標ではなく、同条件の試遊で比較する目標。
3. 難しくする軸は射線・タイミング・優先順位。敵数、弾速、耐久、NOISE密度を同じ区切りで一括増加させない。
4. 回避可能な連続した空間を確保し、画面端への押し込みや回収物による被弾強制を避ける。新要素初登場時はNOISEと回収物を重ねない。
5. 被弾後は無敵時間と周辺弾除去で連続被弾を防ぐ。再同期しても必須会話・次章は失わない。高成績は再挑戦の動機とし、エンディング条件にしない。
6. 長い会話中は戦闘を停止。曲を聴くための区間と読むための区間を分離し、SE連打が主旋律を覆わないようにする。

Signalの追尾は初期案として追尾1秒後に直進、同時追尾体1体から開始。編隊は2体→3体、斉射前に隊形を見せる。Breakでは本格的な連動編隊を先取りしない。

Thundercloudは「RESTORE: 既習の規則的射線」「DELETE: 予告付き通路制限」「RESET: パターン再提示」の3フェーズ案。各フェーズ後に対話を挟み、最終的に既存の第四の答えCREATEへ接続する。体力を削り切ることだけで思想的対立を解決しない。攻撃周期・尺はSignal実装後に設計する。

## 音楽・進行・評価の契約

- 楽曲の再生位置を基準にし、時刻越えで大量の敵をまとめて出現させない。会話・メニュー・タブ非表示ではSTGと音声を一緒に停止する将来仕様とする。
- Storyの初回通過は曲の既存ゲートと会話を尊重する。途中ロードは安全な区間頭から再開し、済んだ会話・報酬を重複実行しない。
- 通常クリアは区間完走。PERFECTは無被弾・再同期なし・指定回収完了・指定NODE見逃しなしを共通の考え方とし、具体的な数はステージごとに事前表示する。Space Homeは対象外。
- 継続用のクリア記録とベスト成績を分け、低成績の再挑戦で報酬を取り消さない。新たなセーブ項目には旧セーブの既定値を用意する。これらは未実装の統合要件。
- [Break詳細設計](STG_BREAK_STAGE2_DESIGN.md)に初回進行、再挑戦、報酬、判定を定義する。

## STG対応背景の制作要件

全15曲の方向性・正式パスは[全曲ビジュアル方針](FULL_TRACK_VISUAL_DIRECTION.md)と[backgroundTargets.ts](../data/backgroundTargets.ts)を正本とする。新規15枚の単位は曲ごとの基本背景であり、Cityの時間帯差分やGadgetの各部屋など既存追加素材を廃止しない。

### 構図・レイヤー

- 16:9、推奨1920×1080 WebP。背景、任意の遠景・前景差分、UI、敵、自機、弾、回収物、警告は別レイヤー。文字・弾幕・NODE・照準を絵に焼き込まない。
- 座標は画面左上(0,0)、右下(1,1)。STG用の低密度領域はx=0.07〜0.95 / y=0.13〜0.87。特に自機側x=0.07〜0.45を暗め・低コントラストにし、右の出現領域x=0.82〜1.0にも強い発光物を置かない。
- 上端12%はHUD、下端18%は短い案内用に模様を抑える。これは背景の余白基準であり、操作領域の縮小指定ではない。案内やEchoが戦闘を覆う場合はUI側を移すか安全区間に限定する。現行Load Roadの案内枠も将来QA対象。
- 遠近の消失点は中央〜右寄りに置けるが、自機や敵弾の背後に白い光源を集中させない。手前の柱・枝・破片で横方向の視線を分断しない。
- シアンの回収物、琥珀の六角NODE、橙の丸い敵弾、赤の角張ったNOISEが、輪郭と形でも区別できること。背景に同サイズ・同輝度の点群を散らさない。
- 前景は外周中心、操作領域への張り出しは避ける。稲光・グリッチはゲーム側で制御し、攻撃予告と競合させない。reduced-motionでも静止画だけで意味と読みやすさが成立すること。
- `object-fit: contain`で完成する構図を基本とする。16:9、4:3、狭幅の表示で余白・クロップ・UI重なりを確認し、ゲーム判定領域と背景表示領域のずれをチェックする。

### 制作・承認ゲート

まず全15曲の静止画候補を揃える。5曲は同じ背景を探索／Listening／STGで共用できるか、仮の自機・弾・HUDを重ねて確認する。視認性を損なう場合のみ、同じ構図の暗い戦闘用差分を追加候補にする。

採用前に、最明部で敵弾が見える、シールド開閉が色以外で読める、最大密度でも退避路が見える、狭幅でHUDと案内が操作領域を塞がない、停止画でも美しい、の5点を確認する。[アート承認フロー](ART_ASSET_PIPELINE.md)に従い、未承認候補は自動表示しない。
